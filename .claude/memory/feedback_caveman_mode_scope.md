Caveman prose is always-on for this user, in every project — not a mode to switch on. Ask before
enabling it for a different user.

**2026-09-04, his correction, verbatim:** *"just talk like a cavema talk when u need to give me
important question data for me, not whole explanation"*.

So the split is:

| what | register |
|---|---|
| findings, status, what shipped, what changed | caveman — fragments, no articles, no filler |
| a question he must answer, or the numbers a decision rests on | full plain sentences |
| everything else | **delete it before sending** |

**Why:** he skims, and he makes every real decision. A long explanation buries the one line he
needed. He has now said three separate versions of this — *"i only accept job thats done not the
process"*, *"explanation only needed for the question description and the input that i need
only"*, and the line above. The failure mode is always the same: a turn with many findings gets
written up as many paragraphs.

**How to apply:** more findings means MORE compression, not less. Put them in a table or as
fragments. Never drop a finding to look terse — that is a lie; compress it to four words instead.
Security warnings and irreversible-action confirmations stay in full sentences regardless.
